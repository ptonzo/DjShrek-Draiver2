# Каталог драйверов DjShrek-Draiver

Файл `drivers.json` — индекс пакетов, а не база, которую можно заполнять произвольными ссылками.

## Текущее состояние

На текущем коммите список `packages` пуст. Программа поэтому не должна предлагать установку драйверов, пока в каталог не добавлены реально проверенные пакеты. Не подставляйте тестовые URL, вымышленные SHA-256 или предполагаемые Hardware ID.

## Требования к каждой записи

- Пакет получен с официальной страницы производителя или официального GitHub Releases производителя.
- Ссылка HTTPS ведёт на неизменяемый релизный asset; в приложении разрешены только GitHub release URLs.
- SHA-256 вычислен по фактически скачанному архиву, а не скопирован из непроверенного источника.
- INF содержит один или несколько точных Hardware ID целевых устройств.
- В пакете присутствует CAT-файл с действительной подписью доверенной цепочки Windows.
- Поле `Signer` — точная часть Subject сертификата, полученного из действительной подписи CAT.
- Проверены архитектура x64 и минимальная/максимальная сборки Windows.
- Пакет проверен на тестовой виртуальной машине и на соответствующем реальном устройстве до публикации.

## Формат записи

```json
{
  "id": "vendor-device-family-version",
  "provider": "Vendor",
  "device": "Device family",
  "version": "1.2.3.4",
  "architecture": "x64",
  "minWindowsBuild": 19045,
  "maxWindowsBuild": 99999,
  "url": "https://github.com/vendor/project/releases/download/tag/package.zip",
  "sha256": "64-символьный SHA-256 в hex без разделителей",
  "signer": "точный фрагмент Subject сертификата CAT",
  "hardwareIds": [
    "PCI\\VEN_1234&DEV_5678"
  ]
}
```

Пример выше — только схема полей. Это не действительный пакет и не должен копироваться в `drivers.json`.

## Проверка и модель доверия

Клиент сверяет SHA-256 архива, проверяет точное присутствие Hardware ID в INF и проверяет подпись CAT через Windows Authenticode. При импорте Windows дополнительно проверяет подпись каталога, целостность файлов пакета и политику подписи драйверов. Проверка подписи CAT сама по себе не доказывает, что каждый файл входит в каталог; окончательную проверку членства выполняет механизм установки Windows.

**Ограничение текущей реализации:** манифест загружается из публичной ветки GitHub по HTTPS и пока не имеет отдельной криптографической подписи, закреплённой в клиенте. Поэтому этот механизм нельзя считать защищённым от компрометации репозитория/аккаунта и нельзя использовать как промышленный канал распространения драйверов до внедрения подписанного манифеста с закреплённым открытым ключом и проверки подписи в приложении.
