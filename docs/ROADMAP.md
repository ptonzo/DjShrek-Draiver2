## Этап 2 — база производителей и каталогов

- [x] Единый реестр официальных источников NVIDIA, AMD, Intel, Realtek, Qualcomm, MediaTek, Broadcom и основных OEM.
- [x] Определение приоритетного домена по Hardware ID (PCI/USB/HDAUDIO) с резервным определением по производителю устройства/драйвера.
- [x] Поиск по Hardware ID ограничивается доменом определённого производителя и отдельно помеченными независимыми каталогами.
- [x] NVIDIA: подключён официальный lookup к обнаруженным GPU; нечеткие названия не принимаются, выдаются только найденные официальные страницы.
- [x] Первые машинно-читаемые OEM-адаптеры Lenovo SCCM catalogv2.xml и Dell DriverPackCatalog CAB/XML: выбор пакетов по MTM/System ID, ОС, архитектуре и прямым ссылкам.
- [x] NVIDIA lookupValueSearch/processFind: получение списка продуктов и ОС из официального XML API, точное сопоставление имени GPU и ссылки на страницу результатов; пакет и INF автоматически не подтверждаются.
- [ ] Машинно-читаемые каталоги AMD/Intel. Для AMD добавлен только честно маркированный переход на официальный Drivers and Support по обнаруженному VEN_1002/VEN_1022; это не каталог пакетов и не считается завершением адаптера.
- [ ] Полноценный каталог пакетов Acer (сейчас доступна только SMBIOS-идентификация и ссылка на официальный портал).
- [x] MSI Support Panel API: получение драйверов для модели платы и метаданных SHA-256 из ответа каталога.
- [x] GIGABYTE DownloadCenter API: каталог материнских плат, карточка продукта и перечень пакетов драйверов.
- [ ] ASUS ProductV2/GetPDDrivers и Product.asmx/GetPDLevel: низкоуровневый API-клиент принимает только реальные PDId/PDHashedId; автоматическое разрешение этих идентификаторов из SMBIOS-модели не реализовано. До этого приложение показывает только официальный портал поддержки и не формирует фиктивные результаты.
- [x] Получение модельных пакетов Dell по SMBIOS System ID, Lenovo по Machine Type (MTM) и HP по SMBIOS SystemSKU.
- [x] Автоматическое получение метаданных OEM-модели HP из HP Client Driver Pack Catalog.
- [ ] Автоматическое получение списка драйверов ASUS: требуется изучить и связать реальные уровни Product.asmx/GetPDLevel с точным ProductId/PDHashedId перед запросом ProductV2.
- [x] Получение SMBIOS-идентификаторов Acer и переход к официальной странице Drivers and Manuals без автоматической отправки серийного номера.
- [ ] Автоматическое получение машинно-читаемых метаданных и пакетов Acer.
- [ ] Подписанный ECDSA-манифест каталога с закреплённым открытым ключом: требуется обеспечить подтверждённое соответствие подписи опубликованному payload и устойчивый процесс безопасной подписи обновлений.
- [ ] Обновление базы источников с криптографической проверкой: до завершения настройки ключевого материала используется встроенный реестр; удалённый манифест не должен считаться доверенным только по HTTPS.

Реестр источников — это маршрутизация поиска, а не база готовых драйверов. Сейчас модельные пакеты извлекаются из каталогов Lenovo, Dell и HP. Реестр источников обновляется из подписанного манифеста, а при отсутствии сети используется встроенная база. Эти записи не являются подтверждёнными обновлениями отдельных устройств: версии драйверов извлекаются из INF после загрузки, а пакет проходит общий preflight INF/CAT. Для Dell и HP CAB проверяются через Windows Get-AuthenticodeSignature: требуется статус Valid и сертификат соответствующего издателя. Это проверка подписи и цепочки средствами Windows; после извлечения пакет всё равно проходит отдельную проверку INF/CAT.

## Важное ограничение текущей версии

Текущий поиск находит официальные страницы поддержки, но не является полноценным каталогом готовых драйверных пакетов. Он не подтверждает автоматически версию и совместимость пакета, не скачивает драйвер и не выполняет автоматическую установку. Эти возможности нельзя считать реализованными до прохождения перечисленных проверок.
